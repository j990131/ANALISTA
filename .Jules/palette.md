## 2024-03-24 - Interactive Accessibility in Dual Implementations
**Learning:** This project requires components in Spanish, meaning ARIA attributes like `aria-label` for icons and dynamically created tabs need to explicitly match the language (e.g., 'Producto anterior', 'Ver producto ${i + 1}') for native screen reader usability. Furthermore, when syncing identical components between vanilla HTML and React, interactive state logic like `aria-selected` must be manually applied through Javascript (`setAttribute`) in the HTML version to achieve feature parity with declarative updates in the React version. Missing `role="tab"` or `aria-live="polite"` completely obscures these visual behaviors for visually impaired users.
**Action:** When adding accessibility layers across dual HTML/React components, I must manually interpolate text in Spanish and write explicit JS DOM manipulations for the HTML implementations to correctly handle state-based ARIA attributes (e.g., `aria-selected="true/false"`) while maintaining sync with the React component behaviors.
